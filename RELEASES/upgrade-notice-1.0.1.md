# PAIOS 升级通知 · v1.0.1（统一版）

> 发件人：Evan（平台维护者）
> 收件人：三位 PAIOS 用户（Case-01 / Case-02 / Case-03）
> 发布日期：2026-07-10
> **性质：非强制 · 约 2 分钟 · 不做也不影响现有使用**

---

## 一句话

PAIOS 发布了 v1.0.1。这是一次**纯新增、不破坏**的小版本。你**什么都不用做**也能继续用；如果想让系统"认识"你的使用场景，花 2 分钟填一个文件即可。

---

## 这次加了什么（对你有什么用）

1. **实例身份声明**：PAIOS 现在能知道"这是谁在用、主要干什么"。未来我（维护者）可以汇总三个人的使用情况，**不打扰你们各自的使用**，只做匿名统计。
2. **升级机制**：以后每次发版都会有这样一份统一通知 + 版本号，你随时知道"我升到哪了、要不要升"，不会被悄悄改动。

> 这些都不影响你现在的任何文件、知识和自动化配置。

---

## 你需要做吗？（可选）

**不填也能用，完全没影响。**

如果你愿意让系统带上你的场景标签（推荐，2 分钟），做这两步：

### 第一步：填一个文件

在你 PAIOS 目录下的 `PAIOS-Usage/profile.yaml`（没有就新建），按你的实际情况填：

```yaml
schema: 1

instance:
  id: case-01        # ← 改成你自己的：case-01 / case-02 / case-03

profile:
  primary: work      # ← 主场景：work（工作）/ personal（个人）/ study（考研）
  secondary:
    - office         # ← 次要场景，可删可改

owner:
  alias: user-a      # ← 你的别名：user-a / user-b / user-c

privacy:
  manifest: share    # ← share（允许被汇总）/ private（不汇总）
```

三个人的填写参考：

| 你 | `instance.id` | `profile.primary` | `owner.alias` | 典型使用 |
|----|---------------|-------------------|---------------|----------|
| 用户 A | `case-01` | `work` | `user-a` | 白天日常工作、社区事务 |
| 用户 B | `case-02` | `personal` | `user-b` | 晚上整理个人档案 |
| 用户 C | `case-03` | `study` | `user-c` | 考研复习 |

### 第二步：自检（可选）

运行一次采集脚本，确认声明生效：

```bash
python 40_AUTOMATION/05_SCRIPTS/collect_manifest.py
```

生成 `PAIOS-Usage/manifest.yaml`，里面有 `core_version: 1.0.1` 即表示升级登记完成。

---

## 我不做会怎样？

**完全没事。** 不填 `profile.yaml`，系统会自动用一串随机 ID 代替，功能照常。只是汇总统计时你的实例会显示为"未命名"，我分不清是谁而已。

---

## 重要原则

- **你的数据永远归你**：PAIOS 升级绝不会覆盖你的知识库、照片、项目、配置。
- **升级永远自愿**：这是你的个人系统，不是 SaaS。是否升级、何时升级，由你决定。
- **一次通知，长期有效**：以后的版本都会沿用这套通知机制。
