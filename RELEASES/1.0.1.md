# PAIOS v1.0.1 Release Notes

**发布日期**：2026-07-10
**类型**：非破坏性（Non-breaking）功能新增
**兼容性基线**：`core_version` 1.0.0 → 1.0.1
**触发策略**：本次仅新增能力，未触及顶层目录结构，符合 `SYSTEM_VERSION.md` 架构冻结策略。

---

## 新增（What's New）

| 模块 | 说明 | 关联 |
|------|------|------|
| 联邦式实例清单（FIM） | 多实例状态下，每个 PAIOS 实例可声明自己的身份与场景画像，汇总方只读采集而不打扰 | ADR-0013 |
| 升级机制（Upgrade Mechanism） | 定义 Core / Workspace / Upgrade 三层 + 版本化发布范式，作为平台级原则 | ADR-0014 |
| 清单采集脚本 | `40_AUTOMATION/05_SCRIPTS/collect_manifest.py`（注册号 SCRIPT-0009），只读现有结构生成 `manifest.yaml` | SCRIPT-0009 |
| 实例身份声明 | `PAIOS-Usage/profile.yaml` 模板：声明 `instance.id` / `profile.primary` / `owner.alias` / `privacy` | ADR-0013 |

---

## 影响（Impact）

- **无破坏性**：现有目录结构、知识库、配置、自动化规则一律不动。
- 老用户（v1.0.0）打开系统后**一切照旧**，无需任何动作也能继续用。
- 新增文件位于 `PAIOS-Usage/`（实例资产）与 `RELEASES/`（发布文档），均为纯新增。

---

## 需要用户做（Required Action）

**可选**，约 2 分钟：

1. 在 `PAIOS-Usage/` 下创建（或确认存在）`profile.yaml`，按自身场景填写：
   - `instance.id`：实例标识（如 `case-01` / `case-02` / `case-03`）
   - `profile.primary`：主场景（`work` / `personal` / `study`）
   - `owner.alias`：使用者别名（如 `user-a` / `user-b` / `user-c`）
   - `privacy.manifest`：`share`（允许被汇总）或 `private`（不汇总）
2. （可选）运行 `python 40_AUTOMATION/05_SCRIPTS/collect_manifest.py` 生成 `manifest.yaml`，自检声明是否生效。

> 不填也不影响任何现有功能。这只是为后续"多实例汇总"打基础。

---

## 兼容性（Compatibility）

- `core_version`：1.0.1
- `manifest_version`：1（FIM 协议首版，见 ADR-0013）
- 与 v1.0.0 完全向前兼容：未声明 `profile.yaml` 时，manifest 自动回退为 `instance.id = <UUID>`，不报错。

---

## 迁移（Migration）

- **本次无迁移脚本**。
- 所有物理结构变更（Core/Workspace 分离、`migrations/`、`migrate.py`）推迟到 Phase B，触发条件见 ADR-0014。
- 用户资产（Workspace）永不被 Core 升级覆盖——这是铁律。

---

## 升级流程（用户侧，三步）

1. **收到通知**：开发者发布本 Release Notes + 统一升级通知（非强制）。
2. **自行决定**：读完"影响"与"需要用户做"，选择是否执行（不执行也行）。
3. **声明版本**：执行 `collect_manifest.py` 后，`manifest.yaml` 自动携带 `core_version: 1.0.1`，汇总方即知"已升级"。
