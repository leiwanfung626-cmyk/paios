# PAIOS 过渡期规则（2026-06-29）

## 核心原则

**Workspace 永远选 F，永远。**

所有 Codex/Reasonix/ChatGPT 会话，项目目录始终设为：
```
E:\PAIOS
```

## 三盘定位

| 盘 | 角色 | 编辑权 | 说明 |
|----|------|--------|------|
| **E:\PAIOS** | 唯一工作台 | ✅ 编辑 | 所有新内容、新项目、新脚本、新规则 |
| **G:\workspace** | 业务数据源 | ⚠️ 只读改引用 | 26 个 Excel 不动，F 项目通过 source.md 引用 |
| **H:\workspace** | 历史知识源 | ⚠️ 只读 | 按需迁移到 F 后标记 Legacy |

## 操作规则

### 1. 所有新工作只进 F
新的笔记、项目、脚本、Agent、SOP、规则——全部直接放 F，不要再放 H 或 G。

### 2. 引用业务数据，不复制
需要 G 盘的 Excel 时，在 F 的项目里写 source.md：
```markdown
数据来源：G:\workspace\01_Projects\鹤城镇吸毒人员档案_清洗后.xlsx
规则：不复制，不修改，用 Python 直接读取原始文件
```

### 3. 历史知识按需迁移
不批量复制 1,615 篇。每天最多 5 篇，流程：
```
H:\workspace → 50_IMPORT/Pending → 验证 → 20_KNOWLEDGE → H 版标记 Legacy
```

### 4. 唯一编辑源
一旦内容迁移到 F 并经过 validate，H 或 G 中对应文件立即停止编辑。
**同一份内容不能在两个地方同时修改。**

## Codex 项目目录选择

| 场景 | 目录 |
|------|------|
| 日常 AI 协作 | `E:\PAIOS` |
| 修改 Installer | `E:\PAIOS`（或引用 H:\...\installer\ 的源码路径） |
| 处理 G 盘数据 | 工作台在 F，通过 source.md 引用 G |
| 从 H 迁移知识 | 工作台在 F，从 H 读取 → 处理 → 写入 F |

## 过渡阶段（3-6 个月）

| 阶段 | 状态 |
|------|------|
| 当前 | F 承担所有新工作，H/G 正常访问 |
| 1-3 月 | 真正需要的内容完成迁移 |
| 3-6 月 | H/G 进入只读，F 成为唯一入口 |
| 之后 | H/G 保留不删，作为可追溯的历史备份 |
