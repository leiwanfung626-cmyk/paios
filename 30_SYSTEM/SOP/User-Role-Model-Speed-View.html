给 Case-02（Personal）/ Case-03（Study）看的一张图 —— 你只管用好平台，别碰平台本身

角色你是什么角色？

实例角色对 Core 的权限你日常做什么
Case-01Platform Maintainer（开发者）读写全权（唯一写入口）开发平台、架构、发布、聚合 Fleet
Case-02Platform User（Personal）只读（git pull）写 Workspace、用平台、反馈、publish Manifest
Case-03Platform User（Study）只读（git pull）写 Workspace、用平台、反馈、publish Manifest

一句话：Core 的唯一写入口是 Case-01。 Case-02/03 是平台使用者，不是平台开发者。

流向数据怎么流动？（单向）

Core（平台能力）
↑ git pull（只读）
Case-01（Developer / Maintainer）
│ 发布 Release（Tag vX.Y.Z）
↓
Case-02（User）
写 Workspace
Case-03（User）
写 Workspace
│ publish Manifest（out-of-band）
↓
F:\Fleet\incoming\case-XX.yaml → Developer Review

User → Core：无（永不 push / 永不 merge / 永不改平台文件）。Manifest 经 out-of-band publish 回流，不经 Core 仓库。

✅ 你能做

  • 写 Workspace（随便写）
  • git pull 升级平台
  • collect_manifest + publish 回流状态
  • 提 Issue / Feedback 给 Developer

❌ 你不能做

  • git push Core（你只有 pull 权限）
  • merge 远端
  • 编辑 30_SYSTEM/ 40_AUTOMATION/ RELEASES/
  • 自行升级平台结构
