# PAIOS 执行宪法 SOP（v1.0）

## 0. 核心原则（唯一真理）

所有任务必须进入生命周期系统，否则不处理、不沉淀、不追踪。

PAIOS 的唯一有效工作空间：

```
E:/PAIOS
```

---

## 1. 任务入口规则（Capture）

### 1.1 所有任务第一动作：进入 Inbox

```
00_CAPTURE/Inbox.md
```

写法：

```markdown
- [ ] 任务描述（简洁可执行）
```

**禁止行为：**
- ❌ 直接开始做任务不记录
- ❌ 直接建 WORK 文件夹不入 Inbox
- ❌ 在脑内管理任务

---

## 2. 执行规则（Work）

### 2.1 只有"确认要做"的任务才能进入 WORK

标准路径：

```
10_WORK/任务名/
```

标准结构：

```
10_WORK/任务名/
├── notes.md        # 过程记录
├── inputs/         # 原始材料
└── outputs/        # 产出结果
```

**创建 WORK 的触发条件：**
- 已从 Inbox 选中任务
- 明确开始执行
- 不再是"想法阶段"

---

## 3. 会话规则（AI 工作区）

### 3.1 唯一推荐会话根目录

```
E:/PAIOS
```

**原则：**
- 会话 ≠ 存储结构
- 会话只是执行入口
- 所有路径必须可回溯到 PAIOS

**禁止：**
- ❌ global 作为任务工作区
- ❌ 任意目录启动 PAIOS 任务

---

## 4. 外部文件规则（夸克盘）

### 4.1 原始业务文件存这里

```
E:\QuarkSync\DATA
```

类型：
- docx
- xlsx
- pdf
- 原始业务材料

### 4.2 PAIOS 只接收"提炼结果"

进入：

```
20_KNOWLEDGE/
```

**原则：** 原始文件不进知识系统，只进"提炼后的认知"。

---

## 5. 任务结束规则（Close Loop）

任务结束必须执行 **三选一**：

### A. 知识沉淀

```
20_KNOWLEDGE/
```

适用：
- 方法论
- 经验总结
- 可复用策略

### B. 系统固化

```
30_SYSTEM/
40_AUTOMATION/
```

适用：
- 规则
- 脚本
- 自动化流程

### C. 丢弃归档

```
90_ARCHIVE/
```

适用：
- 一次性任务
- 无复用价值内容

---

## 6. AI 协作规则（关键）

**AI 负责：**
- 创建 WORK 目录
- 写文件
- 结构化整理
- 提炼内容
- Git 提交（如适用）

**人负责：**
- 选择任务是否进入系统
- 判断是否沉淀知识
- 做"价值决策"

---

## 7. 一句话操作模型（最重要）

```
Capture → Work → Knowledge/System → Archive
```

---

## 8. 最短执行指令集

你可以永远只用三句话驱动系统：

| 指令 | 说 | AI 执行 |
|------|----|---------|
| ① 记录任务 | "我要开始 XXX" | 写入 Inbox |
| ② 执行任务 | "开始处理 XXX" | 建 WORK 目录并开始 |
| ③ 收尾沉淀 | "这个任务做完了，帮我整理" | 三选一完成沉淀 |

---

## 9. 系统边界（强约束）

| 层级 | 用途 | 禁止 |
|------|------|------|
| **PAIOS** | 结构化长期系统 | — |
| **Quark** | 原始数据仓库 | 不进 Git |
| **会话** | 临时执行层 | 不替代存储 |
| **global** | 非系统区域 | ❌ 禁止用于 PAIOS 任务 |
