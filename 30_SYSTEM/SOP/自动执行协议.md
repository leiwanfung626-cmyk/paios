# PAIOS 自动执行协议（Auto Execution Protocol v1.0）

## 0. 核心变化（和 SOP 的区别）

**SOP 是：** 你驱动系统

**自动协议是：** 系统驱动流程，你只做决策点

---

## 1. 系统触发规则（Trigger Layer）

任何输入满足以下之一，自动进入 PAIOS 流程：

### Trigger A：任务声明

```
我要开始 XXX
开始处理 XXX
帮我做 XXX
```

→ 自动进入 Capture

### Trigger B：隐式任务

```
分析 / 设计 / 总结 / 优化 / 排查 / 对比 / 方案
```

→ 自动判定为 Task Candidate（任务候选）

### Trigger C：文件输入

```
上传 / 粘贴 docx / xlsx / pdf / 代码 / 日志
```

→ 自动进入 WORK 或 KNOWLEDGE 分流判断

---

## 2. 自动分流系统（Routing Engine）

系统自动判断任务归属：

### 2.1 Capture（默认第一层）

所有任务先进入：

```
00_CAPTURE/Inbox.md
```

**规则：** 不允许跳过 Capture

### 2.2 Work 判断（自动）

如果满足以下任一条件：
- 需要执行步骤
- 需要产出结果
- 需要持续处理

→ 自动创建：

```
10_WORK/任务名/
```

并初始化结构：

```
notes.md
inputs/
outputs/
```

### 2.3 Knowledge 判断（自动）

如果内容满足：
- 可复用方法
- 经验总结
- 抽象规律
- 决策逻辑

→ 自动提炼进入：

```
20_KNOWLEDGE/
```

### 2.4 System 判断（自动）

如果内容满足：
- 规则
- 架构
- 自动化流程
- 约束条件

→ 自动进入：

```
30_SYSTEM/
40_AUTOMATION/
```

---

## 3. 自动执行链（Execution Pipeline）

每个任务默认执行：

```
Capture
   ↓
Work (if needed)
   ↓
Knowledge / System extraction
   ↓
Archive (if irrelevant)
```

---

## 4. AI 自主行为权限（关键）

### ✅ AI 可以自动执行

- 创建 WORK 文件夹
- 创建 notes.md
- 归类任务类型
- 提取知识点
- 写入 Knowledge
- 提交结构化输出
- 建议归档

### ❌ 需要确认

只有两类必须问你：

**① 价值决策**
> 这个内容要不要沉淀？

**② 系统升级**
> 要不要变更规则 / 架构？

---

## 5. 用户交互简化层（UX Layer）

你只需要三种输入：

### ① 启动任务

```
我要做 XXX
```

→ 自动 Capture + Work

### ② 处理过程

```
继续 / 优化 / 改一下
```

→ 在当前 WORK 内迭代

### ③ 结束任务

```
完成了
```

→ 自动触发：知识提取、系统判断、归档建议

---

## 6. 文件系统自动决策模型（核心）

| 输入类型 | 系统行为 |
|---------|---------|
| 任务 | Capture + Work |
| 知识 | Knowledge |
| 规则 | System |
| 垃圾/一次性 | Archive |

---

## 7. 权重模型（决策引擎）

每个内容评分：

| 维度 | 说明 |
|------|------|
| **Reusability**（复用性） | 这个内容以后还会用到吗？ |
| **Structure**（结构性） | 它适合结构化存储吗？ |
| **Automation potential**（自动化潜力） | 能变成规则或脚本吗？ |

**评分结果：**
- 高 → SYSTEM
- 中 → KNOWLEDGE
- 低 → ARCHIVE

---

## 8. 最终形态（一句话）

> **你只负责"说想做什么"，系统负责"怎么存 + 怎么分 + 怎么沉淀"。**
