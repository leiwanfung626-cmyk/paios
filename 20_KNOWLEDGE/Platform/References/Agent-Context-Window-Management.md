### 章节1：什么是上下文（00:48 - 07:55）

**核心概念**：
- **上下文窗口（Context Window）**：Agent 单次会话能"看见"的全部信息量上限，单位是 token
- **典型上限**：
  - GPT-4o: 128K token
  - Claude Sonnet: 200K token
  - Gemini 1.5 Pro: 1M token（但实际有效注意力远小于此）
- **上下文占用率** = 已用 token / 上限

**类比**：上下文像 Agent 的"短期工作记忆"。人脑同时能记 7±2 个信息块，Agent 能记更多但有上限。占用率超 80% 后，关键信息开始被"挤出"注意力。

### 章节2：上下文快速积累的危害（07:55 - 09:28）

**四大危害**：

1. **早期信息遗忘**（"中间遗忘"效应）
   - 上下文越长，模型对中间部分的注意力衰减
   - 系统提示词、早期对话的关键约束容易被忽略

2. **响应变慢**
   - 每次推理都要处理整个上下文
   - 占用率 90% 时响应时间可能比 30% 时慢 3-5 倍

3. **成本上升**
   - 按 token 计费的模型，输入 token 也算钱
   - 同一对话第 20 轮的成本可能是第 1 轮的 10 倍以上

4. **指令遵循下降**
   - 长上下文中，早期系统指令的权重降低
   - Agent 容易"跑偏"，忽略早期约束

**典型的快速积累场景**：
- 长文档逐段处理（不拆分）
- 一个会话塞多个不相关任务
- 大量粘贴错误日志、整页代码
- 工具调用结果未压缩直接进上下文

### 章节3：Agent 上下文管理经验（09:28 - 14:51）

**核心原则**：上下文外置（Context Externalization）

**六大管理手段**：

1. **任务完成开新会话**
   - 一个任务一个 session，不堆积
   - 任务边界清晰时立即 `/clear` 或新开会话

2. **长文档拆分处理**
   - 超过 5K token 的文档按章节/段落分批
   - 每批处理完提取关键信息，原始文本不进下一轮上下文

3. **外部记忆系统分担**
   - 长期记忆放文件（Markdown/JSON）
   - 会话开始时只读入摘要，不读全文
   - **PAIOS 的 memory 机制正是此法**：MEMORY.md + 日志文件

4. **工具结果压缩**
   - 工具返回的大段输出先提炼要点
   - 原始输出存外部，上下文只保留指针

5. **关键指令前置 + 重申**
   - 系统提示词放在最前面
   - 长对话中定期重申关键约束

6. **监控占用率**
   - 部分工具（如 Codex）会显示上下文占用百分比
   - 超 70% 时主动考虑开新会话或外置信息

## 五、可吸收的新点

1. **占用率监控**：PAIOS 目前没有显式监控 Buddy 的上下文占用率。可考虑在 Today.md 的 Status Snapshot 里加一行 "Context Health" 指标。

2. **会话清理节奏**：视频建议任务完成立即清理。PAIOS 可在 TaskUpdate 标记 completed 时，提示是否触发 memory 写入 + 上下文清理。

3. **工具结果压缩 SOP**：目前工具结果（如 agent-browser snapshot）会直接进上下文，可考虑加一步"提取要点后再进对话"的 SOP。
